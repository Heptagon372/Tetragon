## 0. 지금 AI가 하는 일 — 그리고 안 하는 일

[Tetragon.Plugins.Ai](../../src/Tetragon.Plugins.Ai)는 276줄이고, 능력은 셋뿐입니다([Ai.cs](../../src/Tetragon.Plugin.Abstractions/Ai.cs)).

```csharp
public enum AiCapability { Translate, ProductNameSeo, OptionCleanup }
```

파이프라인에서 실제로 쓰이는 곳은 `EnrichmentHandler` 한 군데입니다([Handlers.cs:145,173](../../src/Tetragon.Application/Pipeline/Handlers.cs)):
번역 배치 1회 + SEO 상품명 1회. **상세페이지는 AI가 손대지 않습니다.**

상세페이지는 어떻게 되고 있느냐면 — 공급처가 라이선스를 허용한 경우에만
(`LogisticsKeys.DetailImageLicense == "Y"`) 공급처 HTML을 그대로 씁니다.
허용하지 않으면 `ConsignmentLogistics.DetailHtml`이 `null`이고, 어댑터·엑셀은 **아무것도 넣지 않습니다.**

> **상세 설명이 비어 있는 상품은 전환율이 0에 가깝습니다.**
> [06 판매 플레이북](06-판매-플레이북.md)이 "안 팔리는 이유"로 든 것 중 코드로 막을 수 있는 것이 바로 이겁니다.

동시에 세 가지가 더 새고 있습니다.

| 새는 것 | 근거 |
|---|---|
| **토큰 사용량이 버려짐** | `AiResult.InputTokens/OutputTokens`가 채워지지만 `EnrichmentHandler`가 읽지 않음. **AI 비용을 시스템이 모릅니다** |
| **프롬프트가 하드코딩** | `PromptTemplates.Version = "1.0.0"`, 주석에 "실제 운영에서는 테이블로 이관한다" |
| **한→한 번역** | 도매꾹(ko-KR) 상품도 `Translate`를 탐. v2 Day 0 항목 |

## 1. `AiCapability` 확장

```csharp
public enum AiCapability
{
    Translate,          // 기존
    ProductNameSeo,     // 기존
    OptionCleanup,      // 기존

    AttributeExtract,   // ★ 브랜드·모델번호·원산지·소재·규격 구조화 추출
    DetailCompose,      // ★ 상세페이지 HTML 생성 (텍스트 기반)
    KeywordExtract,     // ★ 검색 키워드·태그
    ImageAudit,         // ★ 이미지에 타사 로고·워터마크·텍스트가 있는지 (vision)
}
```

`AiRouter`([Registries.cs:58](../../src/Tetragon.Infrastructure/Plugins/Registries.cs))는
`Capabilities.Contains(capability) && IsAvailable`로 라우팅하므로, **`ClaudeAiPlugin.Capabilities`에 새 값을 넣기만 하면 됩니다.**
`SimulatedAiPlugin`은 새 능력을 갖지 않고, 키가 없으면 `AiRouter`가 예외를 던집니다 —
`EnrichmentHandler`가 이미 그 `InvalidOperationException`을 잡아 파이프라인을 멈추지 않게 하고 있으므로 동작이 안전합니다.

### 1.1 `AttributeExtract` — 규제 대응이라 우선순위가 높습니다

[05-마켓-규제-2026.md](05-마켓-규제-2026.md)의 결론: **2026-08-01부터 쿠팡은 브랜드/GTIN·모델번호·구매옵션을 필수로 요구**하고, 현재 파이프라인에 그 데이터가 없어 등록이 실패합니다.

공급처는 그 값을 주지 않지만, **상품명·상세·속성 텍스트 안에 들어 있는 경우가 많습니다.**

```
입력  : 상품명 + 공급처 카테고리 + Attributes 전체 + (라이선스 허용 시) 상세 텍스트
출력  : { brand, modelNumber, gtin, origin, material, dimensions, weight, certifications[] }
        확신 없는 필드는 반드시 null. 추측 금지.
```

**규약: 브랜드를 지어내지 않습니다.** 프롬프트에 "확실하지 않으면 null"을 명시하고, 결과가 `null`이면 `"노브랜드"`로 채웁니다 — 지어낸 브랜드로 등록하면 상표권 문제가 되고, 마켓 카탈로그가 엉뚱한 상품에 병합됩니다([02 §3.1](02-아키텍처-v2.md)의 SDP 논의).

결과는 `Product.Attributes`에 표준 키로 들어갑니다.

```csharp
// src/Tetragon.Plugin.Abstractions/Supplier.cs — LogisticsKeys 옆에 신설
public static class IdentityKeys
{
    public const string Brand         = "브랜드";
    public const string ModelNumber   = "모델번호";
    public const string Gtin          = "바코드";
    public const string Origin        = "원산지";
    public const string Material      = "소재";
    public const string Dimensions    = "규격";
    public const string Certification = "인증정보";
    /// <summary>값의 출처 — "supplier" | "ai" | "human". 감사와 신뢰도 판단에 쓴다.</summary>
    public const string IdentitySource = "식별정보출처";
}
```

`IdentitySource`가 중요합니다. AI가 추출한 브랜드와 공급처가 준 브랜드는 신뢰도가 다르고, 나중에 문제가 생겼을 때 **어느 쪽에서 온 값인지 추적할 수 있어야** 합니다.

이 값들은 `ListingPayload.Attributes`를 타고 쿠팡 어댑터의 필수필드 채움 로직으로 흘러갑니다 — **어댑터 코드를 수정하지 않아도 됩니다.**

### 1.2 `DetailCompose`

```
입력  : 상품명(ko), 옵션 그룹·값, AttributeExtract 결과, 카테고리,
        공급처 텍스트 스펙, (라이선스 허용 시에만) 공급처 상세 텍스트
출력  : 단순 HTML — h2/h3/p/ul/li/table/tr/td/strong 만
금지  : <img>, <script>, <style>, <iframe>, 외부 링크, 인라인 CSS
```

**이미지는 AI가 넣지 않습니다.** 후처리에서 `Product.Images`의 URL만 정해진 위치에 삽입합니다(§3.2).

### 1.3 `ImageAudit` (vision)

대표이미지에 **타사 로고·워터마크·한글 텍스트 오버레이**가 있으면 마켓 심사에서 반려되거나 상표권 문제가 됩니다.

```
입력  : 대표이미지 URL 1장 (Claude vision)
출력  : { hasWatermark, hasThirdPartyLogo, hasTextOverlay, textContent?, verdict, reason }
```

`verdict='block'`이면 `content_assets`가 `published`로 갈 수 없습니다.
**비용이 큽니다** — 상품당 1회, 그리고 등록 직전에만 호출합니다. 소싱 후보 200건에 돌리지 않습니다.

## 3. 생성 → 검증 파이프라인

### 3.1 AI 재생성을 하지 않습니다

v2 §4.1의 결정을 그대로 따릅니다.

> 초판은 검증 실패 시 최대 2회 AI 재생성을 지시했습니다. 금칙어는 후처리 치환으로 결정적으로 제거 가능한데
> Claude 호출을 3배로 늘릴 이유가 없고, 재생성이 다른 금칙어를 만들 확률도 있습니다.

```
content.compose          AI 1회
   ↓
결정적 후처리            코드. AI 없음
   ↓
content.verify           검증. AI 없음
   ↓
 통과 → verified          실패 → rejected + attention_item + 원문 유지
```

**`rejected`여도 기존 콘텐츠는 그대로 남습니다.** 나빠지지 않는 것이 좋아지는 것보다 우선입니다.

### 3.2 결정적 후처리 (`ContentSanitizer`)

```csharp
// src/Tetragon.Application/Services/Content/ContentSanitizer.cs
public static SanitizeResult Sanitize(string html, SanitizeContext ctx)
```

| 단계 | 동작 |
|---|---|
| 태그 화이트리스트 | `h2 h3 p ul ol li table thead tbody tr th td strong em br` 외 전부 제거(내용은 보존) |
| 속성 제거 | `style`, `class`, `on*`, `href` 전부 제거 |
| **이미지 삽입** | AI 출력의 `<img>`는 전부 삭제 → `ctx.AllowedImageUrls`(= `Product.Images`)만 정해진 위치에 삽입 |
| 금칙어 치환 | `ComplianceEngine`의 Aho-Corasick 결과로 `Block` 키워드 삭제, `Warn`은 표시만 |
| 과장표현 | "최저가·1위·정품보장" 등 → 삭제 (치환 사전은 `ComplianceRules`에 시드) |
| 길이 | 마켓별 상한으로 절단 (문단 경계 존중) |

**이미지 화이트리스트가 저작권 방어선입니다.** AI가 어디선가 본 URL을 출력해도 통과하지 못합니다.

### 3.3 검증 (`ContentVerifier`)

```
□ 금칙어 잔존 0          ← ComplianceEngine 재사용
□ 브랜드·모델번호 소실 없음 (AttributeExtract 결과가 최종 텍스트에 남아 있는가)
□ 상품명 길이·문자 제약   ← IListingValidator 재사용 (v2 §2.6)
□ 이미지 URL이 전부 Product.Images 소속
□ 숫자 왜곡 없음: 원문에 없던 규격·용량 수치가 생기지 않았는가  ★ 환각 방어
□ 문서 구조: h2 ≥ 1, 본문 200자 이상
```

**다섯 번째가 핵심입니다.** AI가 "용량 500ml"를 지어내면 표시광고법 문제가 됩니다.
검증은 단순합니다 — 출력의 모든 숫자+단위 토큰이 입력에 존재하는지 확인하고, 없으면 `rejected`.

### 3.4 저작권 규약 (v2 §7.5 구현)

| 상황 | 동작 |
|---|---|
| `DetailImagesAllowed == true` | 공급처 상세 텍스트를 입력에 포함. 공급처 이미지 사용 가능 |
| `DetailImagesAllowed != true` | **공급처 상세를 입력에 넣지 않음.** 상품명·옵션·속성만으로 생성 |
| 라이선스 필드가 없는 공급처 | `false`로 취급 — v2 §7.5의 "기본값 = 사용 금지" |

두 번째 경우가 이 기능의 진짜 가치입니다. **지금까지 상세가 비어 있던 상품에 처음으로 상세가 생깁니다.**

## 4. 비용 통제

### 4.1 `external_calls`를 캐시로 씁니다 (v2 §2.3이 이미 설계함)

```
scope = "ai.{capability}"
key   = sha256(model + promptCode + promptVersion + normalizedInput)
```

- 같은 입력·같은 프롬프트 버전 → **호출 없이 저장된 응답 반환.** `ai_usage(cached=1, cost_krw=0)`
- 프롬프트 버전을 올리면 키가 바뀌어 자연스럽게 재생성됩니다 — 캐시 무효화 로직이 따로 없습니다.
- v2 §2.3 규약 4(`request_hash` 불일치 시 거부)가 그대로 적용됩니다.

### 4.2 예산 가드

```csharp
// AutomationPolicy에 추가
public decimal AiDailyBudgetKrw { get; private set; }   // 기본 5,000원
public bool    AiAutoCompose    { get; private set; }   // 기본 false — 사람이 골라서만
```

- 일일 예산 초과 → `work_items.run_after`를 **KST 다음 날 00:05**로 (v2 §2.5의 쿼터 이월과 동일 패턴)
- `content.compose`는 **자동 팬아웃하지 않습니다** (08 §2.1). 사람이 목록을 골라 큐에 넣습니다.
- 예산의 80%를 쓰면 `attention_item('ai.budget')`.

### 4.3 한→한 번역 제거 (v2 Day 0, 한 줄)

```csharp
// EnrichmentHandler — 번역 호출 직전
if (sourceLocale == "ko-KR") { /* Translate 스킵, 원문 유지 */ }
```

도매꾹 전량이 여기 해당합니다. **이 한 줄이 이 문서 세트에서 투자 대비 효과가 가장 큽니다.**
`ai_usage`가 생기면 그 절감액이 숫자로 보입니다.

### 4.4 토큰 회수 (한 줄)

`AiRouter`를 감싸는 얇은 데코레이터를 하나 두고, 모든 `ExecuteAsync` 결과의
`InputTokens/OutputTokens`를 `ai_usage`에 적재합니다. **호출부를 수정하지 않습니다.**

```csharp
// src/Tetragon.Infrastructure/Plugins/MeteredAiRouter.cs
public sealed class MeteredAiProvider(IAiProviderPlugin inner, IAiUsageSink sink) : IAiProviderPlugin
{
    public async Task<AiResult> ExecuteAsync(AiRequest req, CancellationToken ct)
    {
        var result = await inner.ExecuteAsync(req, ct);
        await sink.RecordAsync(inner.Code, req.Capability, result, ct);   // ← 지금 버려지는 값
        return result;
    }
    // 나머지 멤버는 inner로 위임
}
```

## 5. A/B 실험 — 09이 있어야만 성립

**`listing_perf`가 없으면 이 절은 만들지 마십시오.** 무엇이 나아졌는지 판정할 수단이 없습니다.

규칙:

1. **한 번에 한 변수.** 제목과 상세를 동시에 바꾸면 무엇이 효과인지 알 수 없습니다. `content_experiments.kind`가 하나뿐인 이유입니다.
2. **최소 표본**: 노출 1,000회 **그리고** 14일. 둘 다 만족하기 전에는 `winner`를 쓰지 않습니다.
3. **동시 비교가 불가능합니다.** 오픈마켓 리스팅 하나에 두 버전을 동시에 띄울 수 없으므로 **전후 비교(before/after)**입니다. 계절성·경쟁 변화가 섞입니다.
   → **완화**: 같은 카테고리의 손대지 않은 리스팅들을 대조군으로 삼아, 그 기간의 카테고리 전체 CTR 변화를 빼고 봅니다. 완벽하지 않지만 계절성은 상당 부분 제거됩니다.
4. **판정 지표는 CTR과 전환율**입니다. 매출은 가격 변경(09)과 섞이므로 쓰지 않습니다.

```
POST /api/v1/content/experiments  { productId, kind, variantB }
  → variant B를 published로 전환 (기존 published는 superseded)
  → 시작 시점의 listing_perf 스냅샷 저장
  → min_impressions/min_days 도달 시 work_item('content.experiment')이 판정
  → 결과를 attention_item으로 (자동 롤백하지 않음 — 사람이 결정)
```

## 6. 발행 경로

```
content.publish
  → external_calls (scope="market.update.{channel}",
                    key="{listingId}:{assetId}")
  → IMarketplaceAdapter.UpdateAsync(marketItemId, payload, credential, ct)   ★ 기존 메서드
  → 성공: content_assets(state='published', published_at)
          Listing.MarkPriceStockSynced 대신 SyncLogs에 'content' 액션 추가
```

### 6.1 생성 상세를 어디에 끼워 넣는가 — 두 가지 방법과 그 차이

실제 코드에서 공급처 상세 HTML이 소비되는 지점은 **넷**입니다.

| 위치 | 코드 |
|---|---|
| 쿠팡 | `CoupangCategory.cs:333` — `logistics is { DetailImagesAllowed: true, DetailHtml: { Length: > 0 } }` |
| 11번가 | `ElevenStAdapter.cs:71` — 같은 패턴 |
| 엑셀 4종 | `ExcelTemplates.cs:44` `TemplateHelpers.DetailHtml(payload)` — 4개 템플릿이 공유 |
| 스마트스토어 | `SmartStoreAdapter.cs:210` `BuildDetailHtml(payload)` — **`Logistics`를 아예 보지 않는 별도 구현** |

그리고 `ListingPayloadBuilder.Build`는 `Logistics = ConsignmentLogistics.FromAttributes(product.Attributes, …)` 한 줄로 그 값을 만듭니다([ListingPayloadBuilder.cs](../../src/Tetragon.Application/Services/ListingPayloadBuilder.cs), 65줄).

**방법 A — 어댑터 무수정 (권하지 않음)**
빌더에서 `DetailHtml = 생성물`, `DetailImagesAllowed = true`로 덮어씁니다. 어댑터를 한 줄도 안 고쳐도 됩니다.
그런데 `DetailImagesAllowed`는 **"공급처 상세 이미지를 재사용해도 되는가"**라는 저작권 플래그입니다. 이걸 콘텐츠 유무 신호로 겸용하면 v2 §7.5의 "기본값 = 사용 금지"가 무너지고, 같은 플래그를 읽는 `ProductEndpoints.cs:143`(상세 HTML 조회)과 `LinkPreview.HasDetailHtml`의 의미까지 흔들립니다. **편한 만큼 나중에 비쌉니다.**

**방법 B — 전용 필드 (권장, 수정 3곳)**

```csharp
// ListingPayload에 추가 (init 전용이라 기존 생성부는 무수정)
/// <summary>AI로 생성해 승인·발행한 상세 HTML. 공급처 HTML보다 우선한다.</summary>
public string? ComposedDetailHtml { get; init; }

// ListingPayloadBuilder.Build에 선택 인자 추가 — 기존 호출부 무수정
public ListingPayload Build(Product product, string? composedDetailHtml = null)

// 소비 지점 3곳이 같은 우선순위 한 줄을 쓴다
var detail = payload.ComposedDetailHtml
          ?? (logistics is { DetailImagesAllowed: true, DetailHtml: { Length: > 0 } h } ? h : null);
```

`TemplateHelpers.DetailHtml` 하나만 고치면 **엑셀 4종이 전부 반영**되므로, 실제 수정은 쿠팡·11번가·`TemplateHelpers` **3곳**입니다.

**스마트스토어는 별도입니다.** `BuildDetailHtml`이 `Logistics`를 보지 않으므로 지금도 공급처 상세를 쓰지 않습니다 — ARCHITECTURE.md §12.4가 "스마트스토어 어댑터는 위탁 물류를 쓰지 않는다"고 지적한 그 문제입니다. 생성 콘텐츠를 여기 넣으려면 그 함수를 따로 고쳐야 하고, **스마트스토어를 실제로 운영 중인지 먼저 확인**하십시오(README "지금 확인해야 할 것" 2번).

## 10. 이 설계가 틀릴 수 있는 지점

1. **AI 생성 상세의 마켓 심사 통과율을 모릅니다.** 마켓이 AI 생성 콘텐츠를 어떻게 다루는지 정책을 확인하지 못했습니다. §6.2 카나리가 전제입니다.
2. **`ImageAudit`의 vision 비용이 예산을 압도할 수 있습니다.** 상품 1만 개에 돌리면 안 됩니다. 등록 직전 1회로 제한했지만, 그래도 대량 등록 시에는 비용이 큽니다. **완화**: 티어 A + 신규 발행분에만.
3. **숫자 환각 검증이 오탐을 냅니다.** "3단"에서 "3층"으로 표현이 바뀌면 걸립니다. 단위가 붙은 수치(cm/ml/kg/개/W)만 검사하고, 서수·형용 숫자는 제외하십시오.
4. **A/B가 전후 비교라 인과가 약합니다** (§5-3). 대조군 보정을 넣어도 "이 상세가 좋아서 팔렸다"를 증명하지 못합니다. 판정은 참고로 쓰고, 명백한 차이(CTR 1.5배 이상)에만 반응하십시오.
5. **`AttributeExtract`가 틀린 브랜드를 넣으면 상표권 문제입니다.** 그래서 "확실하지 않으면 null"을 강제했지만, 모델이 규칙을 어길 수 있습니다. **완화**: 추출된 브랜드는 `IdentitySource='ai'`로 표시하고, 쿠팡 발행 전에 **사람이 목록으로 한 번 훑는 단계**를 두십시오 — 214건이면 10분입니다.
6. **`prompt_templates` 이관 후 프롬프트를 화면에서 고칠 수 있게 되면, 그것도 배포 없는 변경입니다.** 활성 버전 전환에 확인 다이얼로그를 두고, `content_assets.prompt_version`으로 어떤 버전이 무엇을 만들었는지 추적하십시오.
